# Controlled-access workflow

## Public materials

The following materials may be released publicly after institutional review:

- dataset-level metadata and data dictionaries;
- analysis and validation code;
- manuscript figures and aggregate tables that do not create identification risk;
- synthetic or explicitly approved non-identifying examples; and
- the data-access application and Data Use Agreement template.

## Restricted materials

Raw or minimally processed sEEG, speech audio, trial-level annotations,
electrode coordinates, implantation information, and linked clinical or session
metadata should remain in the approved controlled-access repository.

## Application sequence

1. The applicant submits institutional identity, scientific purpose, requested
   data scope, ethics documentation, proposed security controls, and access
   dates.
2. Each proposed user and the supervising PI sign the approved Data Use
   Agreement.
3. The Dataset Access Committee evaluates scientific validity, participant
   consent, ethics, data minimization, and information-security safeguards.
4. Approved users receive time-limited access only to the approved data scope.
5. Access, downloads, incidents, extensions, termination, and deletion
   certification are recorded by the data custodian.

Signing the DUA does not by itself grant access. Access begins only after a
documented approval decision and technical authorization by the data custodian.

## Repository release checklist

- [ ] Replace every bracketed field in the DUA.
- [ ] Confirm the legal data provider and institutional signatory.
- [ ] Name the Dataset Access Committee and data custodian.
- [ ] Add the final repository DOI and access-request URL.
- [ ] Specify the review timeframe and normal access period.
- [ ] Confirm incident-reporting and deletion deadlines.
- [ ] Confirm participant consent permits the proposed controlled sharing.
- [ ] Obtain ethics, legal, information-security, and data-governance approval.
- [ ] Test anonymous reviewer access for journal peer review.
- [ ] Verify that no restricted data are present in Git history or release assets.
